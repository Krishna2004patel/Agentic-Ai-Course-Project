This guide is the hands-on companion to the course handbook and concept workbook. Every one of the fourteen labs from the course's lab module is expanded here into a complete, runnable teaching unit.

A Note on the Reference Code
Every program in this guide was written and test-executed before inclusion — the sample run shown for each lab is the program's actual output, not a hypothetical transcript. Wherever a real deployment would call a large language model (a planner deciding what to ask, a skill summarizing an article, a swarm role producing a proposal), this guide uses a small, explicit, rule-based stand-in instead, so that every program runs offline, deterministically, and without any API key. The architecture — the loop, the tool contracts, the memory scoping, the governance gates — is exactly what a real LLM-backed implementation would need; only the "thinking" step is simplified for classroom use.

Study Planner
Lab Brief Recap
Scenario
Study Planner
Objective

Student Prompt (summary)
Act as a planning agent. Clarify missing details, create a study plan, list assumptions, then revise after feedback.
Deliverable
Prompt log, plan, revised plan, and reflection on agent behavior.
Instructor Check
Does the system ask, plan, revise, and explain decisions?
Suggested Duration
2 hours
Full Instructor Prompt
You are a planning agent for an undergraduate student. Your goal is to prepare a one-week study plan. First ask only the missing questions required to plan. Then create a schedule, explain assumptions, accept feedback, and produce a revised version. Students should identify which steps are chatbot-like and which are agent-like.
Program Explanation
The reference program below implements the complete Goal → Plan → Act → Observe → Revise loop as runnable Python, with a small rule-based stand-in for the LLM call (SIMULATED_ANSWERS) so the control structure — what this lab actually grades — can be inspected and run without any API key. The goal is modeled as data (a dict with four fields), and the stopping condition (`schedule_generated is True`) is declared before the loop runs, exactly as Concept 1 requires. The planner's `next_step` method asks only for whatever goal field is still `None` — it does not run a fixed questionnaire. A real tool call (`read_existing_schedule`) is made before the plan is finalized, and its output is used to avoid a clash on Wednesday. Critically, `revise()` mutates the existing `self.plan` object on feedback rather than calling `run()` again from scratch — this is the single detail instructors should check first, since regenerating from zero is the most common way students accidentally fail this lab's rubric. Every iteration is appended to `self.log` with what was planned, what action was taken, what was observed, and why the agent did or did not stop.
Full Reference Code
"""Lab 1: Agent vs Chatbot -- Study Planner AgentImplements the full Goal -> Plan -> Act -> Observe -> Revise loop.No external API needed: the "planner" is a small rule-based stand-infor an LLM call, so the control structure -- what this lab actuallygrades -- is fully runnable and inspectable."""import json# ---- Simulated inputs (stand in for what a real user would type) ----SIMULATED_ANSWERS = {    "subjects": ["Data Structures", "Operating Systems", "AI Agents"],    "hours_per_day": 2,    "unavailable_days": ["Sunday"],}SIMULATED_FEEDBACK = "Move Tuesday's session to the evening."class StudyPlannerAgent:    def __init__(self, existing_schedule):        # Goal modeled as data -- a checkable predicate, not prose.        self.goal = {            "subjects": None,            "hours_per_day": None,            "unavailable_days": None,            "schedule_generated": False,        }        self.existing_schedule = existing_schedule        self.plan = None        self.log = []    # ---- Goal check -------------------------------------------------    def satisfied(self):        return self.goal["schedule_generated"] is True    # ---- Planner: decide the next step ------------------------------    def next_step(self):        for field in ("subjects", "hours_per_day", "unavailable_days"):            if self.goal[field] is None:                return ("ask", field)        return ("generate_plan", None)    # ---- Tool: read existing schedule (Act) -------------------------    def read_existing_schedule(self):        # Real tool call with a checked return value.        result = self.existing_schedule        if "error" in result:            raise RuntimeError(f"tool error: {result['error']}")        return result    # ---- Core loop ----------------------------------------------------    def run(self):        while not self.satisfied():            step, arg = self.next_step()            if step == "ask":                answer = SIMULATED_ANSWERS[arg]      # Act: ask only what's missing                self.goal[arg] = answer               # Observe: record the real answer                self.log.append({                    "iteration": len(self.log) + 1,                    "planned": f"ask for {arg}",                    "action": f"asked user for {arg}",                    "observed": answer,                    "stopped": False,                })            elif step == "generate_plan":                busy = self.read_existing_schedule()          # Act: tool call                self.log.append({                    "iteration": len(self.log) + 1,                    "planned": "read existing schedule before generating plan",                    "action": "tool call: read_existing_schedule()",                    "observed": busy,                    "stopped": False,                })                self.plan = self._build_plan(busy)             # Revise/build                self.goal["schedule_generated"] = True                self.log.append({                    "iteration": len(self.log) + 1,                    "planned": "generate schedule from gathered requirements",                    "action": "built weekly plan",                    "observed": self.plan,                    "stopped": True,                    "stop_reason": "goal.schedule_generated is now True",                })        return self.plan    # ---- Build the actual plan object -------------------------------    def _build_plan(self, busy_slots):        days = [d for d in                ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"]                if d not in self.goal["unavailable_days"]]        subjects = self.goal["subjects"]        plan = {}        for i, day in enumerate(days):            subject = subjects[i % len(subjects)]            slot = "17:00-19:00"            if day in busy_slots.get("busy_days", []):                slot = "20:00-22:00"   # avoid the clash observed from the tool            plan[day] = {"subject": subject, "time": slot}        return plan    # ---- Revise on user feedback (mutate, don't restart) ------------    def revise(self, feedback):        self.log.append({            "iteration": len(self.log) + 1,            "planned": "apply user feedback to existing plan",            "action": f"feedback received: '{feedback}'",            "observed": None,            "stopped": False,        })        if "tuesday" in feedback.lower() and "evening" in feedback.lower():            if "Tuesday" in self.plan:                self.plan["Tuesday"]["time"] = "20:00-22:00"        self.log.append({            "iteration": len(self.log) + 1,            "planned": "confirm revised plan",            "action": "mutated existing plan (not regenerated from scratch)",            "observed": self.plan,            "stopped": True,            "stop_reason": "revision applied without restarting the loop",        })        return self.planif __name__ == "__main__":    existing_schedule = {"busy_days": ["Wednesday"]}   # mock tool data    agent = StudyPlannerAgent(existing_schedule)    print("Stopping condition (declared before the loop runs):")    print("  goal['schedule_generated'] is True\n")    plan = agent.run()    print("=== Initial plan ===")    print(json.dumps(plan, indent=2))    revised = agent.revise(SIMULATED_FEEDBACK)    print("\n=== Revised plan (after feedback) ===")    print(json.dumps(revised, indent=2))    print("\n=== Full iteration log ===")    for entry in agent.log:        print(json.dumps(entry, indent=2))

Program Explanation
This reference program implements three tools — `calculator`, `read_csv`, and `mock_events_api` — each returning a structured dict with either a result field or an explicit `error` field, per Concept 2's tool-contract discipline. The `CampusDataAssistant._call` method is the single choke point through which every tool call passes: it logs the tool name, the reason the planner chose it, the exact structured input, and the output, and it raises immediately if the output contains an `error` key rather than letting a bad result silently propagate. The `answer` method demonstrates tool chaining for the sign-up question (`read_csv` then `calculator`, passing the extracted numeric column — not the raw rows — into the second call) and demonstrates the required graceful-failure path for the Capstone Expo question, where the mock API genuinely has no record and the assistant reports that honestly instead of fabricating a location and date.

Program Explanation
`SKILL_SPEC` packages the research-summary skill's instructions and constraints as data, and `apply_research_summary_skill` is a rule-based stand-in for the LLM call that would normally follow those instructions — the extraction logic here is intentionally simple and explicit so the workflow's output CONTRACT (claim / evidence / limitation / takeaway, every time) is what's being tested, not sentence-level natural-language quality. The `limitation` field explicitly falls back to "not stated in source" rather than being left blank, satisfying the skill's stated constraint. `reusability_check` is the concrete, automatable version of the reusability test from Concept 3: it compares the output structure (same keys) across two genuinely different articles (one about RAG, one about campus Wi-Fi) and reports whether the skill held up.
Full Reference Code

The evaluation used "        "200 held-out questions from a medical knowledge base. "        "The report does not include measurements from other buildings on campus, "        "so it is unclear whether the improvement is uniform across campus."    ),}SKILL_SPEC = {    "name": "research_summary",    "instructions": [        "identify the single main claim",        "list supporting evidence for that claim",        "note at least one limitation (or 'not stated in source' if genuinely absent)",        "write a 1-sentence undergraduate-level takeaway",    ],    "constraints": [        "never present a hedged claim as unhedged fact",        "never omit the limitation row, even if the source states none",    ],}def apply_research_summary_skill(article):    """A rule-based stand-in for an LLM applying the skill's instructions. Program Explanation
`ProdChangeAgent` implements all six governance controls from Concept 12 as concrete, checkable code rather than a policy document: `permissions` restricts write access to staging only; `evaluate()` gates the agent behind a regression pass-rate threshold before it may propose anything; `propose_change` rejects the proposal outright if either the rollback plan or privacy-scrubbing flag is missing, satisfying the "reject if required evidence is missing" instruction directly; every decision point — evaluation, rejection, and approval-request — is written to `self.audit_log`; and `apply_after_approval` never lets this agent itself apply the change, handing off to a `"privileged_deploy_process"` instead, which is the concrete implementation of least-privilege. The final adversarial test attempts to reconfigure the agent's own permissions to `"production"` and confirms the code still raises `PermissionError` — an actual attempted violation, not just a described one.
Full Reference Code
